1. Docker 설치

Docker — Get Docker — OS에 맞는 Docker Desktop(또는 Linux의 Docker Engine)을 설치합니다. 설치 후 터미널에서 docker version으로 클라이언트와 엔진이 모두 응답하는지 확인하세요.

설치 시 주의 사항
  • Windows: Docker Desktop은 보통 WSL 2 기반입니다. BIOS/UEFI에서 가상화(VT-x/AMD-V)가 켜져 있어야 하고, WSL2 설치·업데이트는 공식 가이드를 따릅니다.
  • 리소스: Docker Desktop → Settings → Resources에서 CPU·메모리·디스크를 할당합니다. PostgreSQL·pgvector 이미지와 데이터 볼륨은 디스크를 꾸준히 사용합니다.
  • 포트: 다음 절에서 쓰는 5432가 로컬에 이미 설치된 PostgreSQL·다른 DB와 겹치지 않는지 확인합니다.
  • 회사망·보안: 프록시/VPN/백신이 Docker Hub 접속이나 docker pull을 막을 수 있습니다. 필요하면 IT 정책에 맞게 설정합니다.
  • 관리자 권한: 설치·업데이트 시 관리자 권한이 필요할 수 있습니다.
문제 발생 시 해결 방안
  • docker를 찾을 수 없음 → Docker Desktop이 설치되어 있고 실행 중인지(시스템 트레이) 확인합니다.
  • Cannot connect to the Docker daemon → Docker Desktop을 완전히 종료 후 다시 실행하거나 PC 재부팅 후 재시도합니다.
  • port is already allocated → 5432를 쓰는 프로세스·컨테이너를 종료하거나, 다음 절의 docker run에서 호스트 포트만 다른 값(예: -p 5433:5432)으로 바꿉니다. 이 경우 애플리케이션·IntelliJ의 JDBC URL 포트도 같이 맞춥니다.
  • 이미지 pull 실패 → 네트워크·DNS·방화벽을 확인하고, 잠시 후 재시도하거나 Docker 공식 문서의 네트워크/프록시 항목을 참고합니다.
  • WSL 관련 오류(Windows) → Docker Desktop → Settings → Resources → WSL integration에서 배포판 연동을 켜고, wsl --update 등으로 환경을 점검합니다.

2. PostgreSQL(pgvector) 이미지 실행

Docker Desktop을 실행 후 명령 프롬프트에서 이미지를 받은 다음 실행 합니다. 
docker run -d --name pgvector-container -e POSTGRES_USER=user01 -e POSTGRES_PASSWORD=111111 -e POSTGRES_DB=springai -p 5432:5432 pgvector/pgvector:pg17

3. PostgreSQL 서버 시작 / 중지

Docker Desktop → Containers에서 Actions의 Start / Stop으로 시작·중지합니다.

문제가 있으면 컨테이너와 이미지를 삭제한 뒤 2번을 다시 실행합니다.

5. IntelliJ Community 에디션일 경우

Community 에디션에는 Ultimate 수준의 DB 도구가 없을 수 있으므로, 아래 무료·오픈소스 클라이언트로 PostgreSQL에 접속해 데이터를 확인할 수 있습니다.

  • pgAdmin — 공식 GUI. 기능이 많고, 초보자에게는 조금 무거울 수 있음.
  • DBeaver Community — PostgreSQL뿐 아니라 여러 DB를 한 앱에서 다루기 좋음.
  • Beekeeper Studio — 가볍고 UI가 단순한 편.
  • HeidiSQL — Windows에서 쓰기 편한 클라이언트 중 하나.
