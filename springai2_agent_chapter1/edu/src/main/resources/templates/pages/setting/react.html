React 프론트엔드 — frontend_agent 프로젝트

Vite · React 19 · TypeScript — 순수 REST Spring Boot 프로젝트 springai2_agent_rest의 /ch1~/ch9, /api, 정적 /imgs와 연동하는 SPA

백엔드는 springai2_agent_rest.zip을 내려받아 원하는 경로에 압축을 푼 뒤, 그 안의 edu 폴더를 Gradle 프로젝트 루트로 IDE에서 엽니다.

프론트는 frontend_agent.zip을 내려받아 압축을 풀고, 나오는 frontend_agent 폴더를 Visual Studio Code(VS Code)에서 프로젝트 루트로 열어 사용합니다(로컬 경로 예: C:\edu\frontend_agent). 본 페이지는 그 디렉터리 구조와 주요 파일 역할을 정리합니다. 백엔드를 띄운 뒤 VS Code 통합 터미널 등에서 해당 폴더 안으로 이동해 npm install → npm run dev로 개발 서버(기본 http://127.0.0.1:5173)를 실행합니다.

Swagger UI 열기: 백엔드가 실행 중일 때, React 주소(127.0.0.1:5173)가 아니라 API 서버 주소로 브라우저에서 접속합니다. 예를 들어 백엔드가 http://localhost:80이면 주소창에 http://localhost:80/swagger-ui.html을 입력합니다. OpenAPI JSON 스펙은 같은 호스트의 http://localhost:80/v3/api-docs입니다(vite.config.ts의 VITE_API_URL과 포트를 맞춥니다). Vite에는 Swagger 경로 프록시가 없으므로, 위처럼 백엔드 origin으로 직접 열거나 필요 시 vite.config.ts에 /swagger-ui·/v3 프록시를 추가할 수 있습니다.

백엔드는 Thymeleaf 없이 JSON·text/plain 등 HTTP API만 제공합니다.

5. 백엔드 REST 계약 요약

아래 API는 springai2_agent_rest의 edu 모듈을 기동했을 때 제공됩니다.

  • 프록시: 개발 시 Vite가 /ch*, /api, /imgs를 VITE_API_URL로 넘깁니다. React는 상대 경로만 호출해도 동일 출처처럼 동작합니다.
  • CORS: 백엔드가 http://localhost:* / 127.0.0.1:* 패턴을 허용하면, 프록시 없이 절대 URL로 API를 호출할 때도 브라우저에서 막히지 않습니다.
  • 전략 분석·SSE: Redis Pub/Sub → SSE. 실습 전 Redis 기동이 필요합니다. workflowId는 POST와 SSE 경로가 반드시 일치해야 합니다.
  • 응답 형식: 문자열 API는 text/plain;charset=UTF-8, 일부는 JSON. 전역 예외는 502(연결 실패)·500과 JSON error 메시지를 사용할 수 있습니다.

6. 실행 및 환경 변수

백엔드 springai2_agent_rest: springai2_agent_rest.zip을 다운로드한 뒤 압축을 풀고, 포함된 edu 디렉터리에서 Spring Boot 애플리케이션을 실행합니다. 전략 분석·SSE 실습에는 Redis 등이 필요할 수 있으니 강의 자료의 환경 절차를 함께 맞춥니다.

프론트 frontend_agent: frontend_agent.zip을 다운로드한 뒤 압축을 풀고, 생성된 frontend_agent 폴더를 VS Code에서 연 뒤, 백엔드가 떠 있는 상태에서 그 폴더(통합 터미널 기준)에서:

npm install
npm run dev
  • VITE_API_URL — Vite 프록시 대상(백엔드 origin). 기본값은 vite.config.ts에서 http://localhost:80.
  • VITE_SPRING_ORIGIN — springImg 등 절대 URL용 백엔드 주소.

프로덕션 빌드: npm run build 후 dist/를 정적 호스팅하거나, 동일 출처로 서빙 시 API 프록시는 웹 서버(nginx 등)에서 구성합니다.

7. 문제 해결(SSE·전략 분석)

  • SSE 로그가 비어 있음: Redis 실행 여부, 백엔드 로그의 Pub/Sub 발행, 브라우저 개발자 도구 Network에서 /api/workflow/stream/… 이벤트 스트림 수신 여부를 확인합니다. event.data가 JSON이 아니면 서버 SSE·Redis 직렬화 설정을 점검합니다.
  • 초기 STARTED·ROUTING 이벤트 누락: 클라이언트가 POST보다 SSE를 먼저 열고, 서버가 이력 replay를 제공하는지 확인합니다(StrategicAnalysisLab이 그 순서를 따름).
  • POST만 4xx/5xx: 응답 본문이 JSON이면 error 필드를 읽습니다. 프록시 대상 VITE_API_URL 포트가 백엔드와 일치하는지 확인합니다.
